# Expert PvP Battle Evidence Contract

Issue #143 extends the existing owned-only PvP Battle Lab with a conservative expert evidence layer. This layer does not manufacture battle results from IV rank, stat product, CP, or Attack IV.

## Freshness boundary

The browser consumes normalized matchup rows only from `data/pvp-battle-lab.json` under `current_simulation.matchups`. The build-time current-data pipeline is responsible for populating that field only from fresh, reviewed PvP inputs. When the field is absent or empty, the UI remains explicitly blocked instead of deriving matchup claims from static collection data.

## Supported normalized matchup row

A row is usable only when it includes enough information to join a result to an owned species and an opponent:

- `pokemon_number` or `attacker_pokemon_number`
- `opponent_id` or `opponent`
- explicit `result`/`outcome` of `win`, `loss`, or `tie`, or a numeric battle rating where greater than 500 is a win, less than 500 is a loss, and exactly 500 is a tie

Optional supported fields include model version, shields, starting energy, starting HP percentage, attack breakpoints, and defense bulkpoints. Unsupported rows remain ignored rather than inferred.

## Exact owned-record mapping

External matchup evidence is species-level evidence, not an owned-record identity. The browser joins it to every exact canonical owned record with the same Pokédex number. Duplicate owned copies remain distinct result rows with their own canonical record IDs.

## Pinned assumptions

A matchup row is excluded when it explicitly conflicts with a supported requested assumption. Supported assumption keys are:

- shields
- starting energy
- starting HP percentage

An absent assumption in the source is treated as unspecified, not contradictory.

## Derived expert views

From supported rows the client can deterministically calculate:

- wins, losses, and ties per exact owned record
- win rate over available normalized opponent rows
- opponents that defeat compared records
- whether at least one compared owned record has a source-backed win against a threat
- source-supplied attack breakpoints and defense bulkpoints

These are summaries of supplied evidence. They are not a replacement for a complete turn-by-turn Pokémon GO PvP simulation engine.

## Safety rules

- Rank 1 is never treated as universally best.
- Attack IV alone is never treated as CMP Attack.
- Missing matchup evidence produces an explicit blocked state.
- Breakpoints and bulkpoints appear only when supplied by a normalized row.
- Current-meta rows must be removed or blocked by the build pipeline when their source expires.
- No expensive investment recommendation is generated by this layer.

## Remaining #143 scope

This increment establishes the expert matchup-result, threat, and breakpoint consumption contract. Completing #143 still requires a reviewed, license-safe normalized battle mechanics/model input capable of deterministic turn-by-turn simulation, configurable baiting/stat stages, and complete current-meta matrix generation rather than normalized result replay alone.
