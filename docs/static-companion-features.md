# Static collection companion features

The human-facing companion remains fully static. Collection data, saved views, goals, annotations, comparison selections, and preferences are not sent to Firebase or another application server.

## Human-facing pages

The generated Pages site exposes three primary surfaces:

- `/` — Collection dashboard and record details.
- `/insights.html` — Collection-wide summaries and drill-downs.
- `/tools.html` — Owned-only planning, duplicate/trade review, goals, notes/labels, and freshness-gated event preparation.

The production build cross-links these pages and includes Tools in the PWA precache.

## Mobile cards and Pokémon details

Below 720 CSS pixels, the desktop table is replaced visually by compact result cards showing identity, CP, IV, level, status, and selected-league PvP information. Details open in a native modal dialog and expose the normalized record, including moves, dates, size, scan fields, and supported Poke Genie PvP league sections.

Record-specific persistent features use canonical identity generated by the build. `identity.record_id` is the exact within-build key used by browser-local annotations and other record-specific tools. Best-effort cross-build identity/provenance semantics are handled by the canonical pipeline and migration layer rather than by inventing a second browser fingerprint system.

Ambiguous cross-build matches are not silently treated as the same physical Pokémon.

## Saved views

Personal saved views contain the current URL query and optional desktop column preferences. They are stored under a versioned `localStorage` key and survive reloads in the same browser profile.

Saved views can be renamed, duplicated, deleted, exported as human-readable JSON, and imported later. Duplicate import names are handled explicitly. Unsupported schema versions and malformed backups fail without mutating the existing saved views.

Browser storage can be cleared by the browser or operating system. Exported JSON is the current backup mechanism. Issue #97 tracks a unified backup/restore envelope across all durable local namespaces.

## Browser-local notes and review labels

The Tools page supports record-specific local labels and free-text notes stored separately from generated collection data.

Annotations are keyed by canonical record ID and use a versioned local schema. Backup/import, clearing, migration, ambiguous-match detection, and orphan states are supported.

A new export does not automatically erase an annotation when canonical identity is preserved. If migration evidence is ambiguous, the note remains unresolved instead of being attached to one of several identical-looking Pokémon.

Local annotation data is visibly distinct from Poke Genie facts and is never written into `data/pokemon.json` by the normal build.

## Collection goals

Goals are browser-local, versioned, and separately exportable/importable. Supported goal predicates use facts that the canonical collection or pinned knowledge layer can actually evaluate.

Unsupported source facts such as shiny/costume completion remain explicitly unsupported until a trustworthy owned-record source or browser-local enrichment layer exists.

## Comparison workspace

Two to six Pokémon can be compared side by side. Selection persists while changing filters or pages during the current browser session. The comparison presents CP, level, IVs, status, moves, and supported Poke Genie league ranking data.

The comparison deliberately does not declare a universal winner. PvP rank, IV percentage, CP, Shadow status, moves, availability, and investment cost answer different questions. A lower value in one column never means another copy is automatically safe to transfer.

## Safety-first duplicate and trade review

Duplicate and trade tools operate on distinct canonical records remaining after conservative duplicate-scan reconciliation.

Supported protection reasons include hundos/nundos, Favorites, Lucky, Shadow/Purified state, unlocked second Charged Moves, strong Poke Genie PvP candidates, and incomplete scans. Supported form/status boundaries are preserved when grouping.

The source contract cannot reliably prove every shiny, costume, background, legacy/current-move, Dynamax, Gigantamax, trade-history, or location fact. Missing values remain uncertainty. Review candidates are never described as automatically safe to transfer or trade.

## Pokémon GO search-string generator

The GO Search dialog translates compatible dashboard filters into a Pokémon GO inventory search string. Each requested condition is labeled as Exact, Approximate, or Not representable. Approximate and omitted conditions are explained before copying.

The operator map has a verification date/source because Pokémon GO search syntax can change. Dashboard filtering and Pokémon GO inventory search are not the same language. Poke Genie PvP rank, scan completeness, arbitrary IV percentages, browser-local labels, canonical record IDs, and several normalized fields have no exact in-game equivalent.

The generator never labels a resulting string safe for blind bulk transfer.

## Planning tools

`tools.html` provides:

- owned-only PvP/PvE team composition;
- deterministic budget optimization and what-if investment scenarios;
- browser-local collection goals;
- safety-first trade planning;
- safety-first duplicate review;
- canonical-ID notes and review labels;
- event preparation that requires a fresh external event snapshot.

Current PvP meta, raid rotations, Rocket lineups, event windows, and similar rotating facts are not inferred from stable collection data when current external data is unavailable.

## Installable offline PWA

The generated site publishes `manifest.webmanifest`, a project-created icon, and a versioned `sw.js` service worker. Hashed application assets and the current collection shell are precached as one build version, including `tools.html`.

HTML and collection JSON use a network-first strategy. When offline, the service worker can return the previously cached build. The UI displays offline state with source/freshness context so cached data is not mistaken for a current fetch. Static hashed assets use cache-first behavior.

Old application caches are deleted only after the new service worker activates. A failed network response is never inserted into the cache as valid collection data. Browser-local views/goals/annotations remain separate from service-worker caches.

## Data-source boundaries

The UI distinguishes:

- Poke Genie owned-record facts;
- stable pinned species/mechanics knowledge;
- deterministic calculated facts/reasoning;
- freshness-aware current external facts;
- browser-local user state;
- unsupported/unknown data.

No layer silently becomes another. This is especially important for destructive or expensive decisions.
